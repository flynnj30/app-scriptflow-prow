# Transcript Studio Integration Fix

## Why the previous version returned HTTP 502

The browser surface itself was working. The 502 was generated by the ScriptFlow server when its outbound connection to `https://transcript-studio-n0nv.onrender.com` failed. A browser-side renderer cannot fix an upstream server-to-server connection failure.

## Fixes in this version

- Uses an IPv4-preferred outbound HTTPS agent for Render-to-Render connectivity.
- Retries transient upstream 5xx responses and connection failures up to 3 times.
- Uses a 90-second upstream timeout to accommodate cold-starting Render services.
- Sends a normal browser User-Agent and Accept headers.
- Preserves GET/HEAD and forwards request bodies for POST/PUT/PATCH/DELETE.
- Returns useful diagnostic JSON for proxy failures instead of an opaque 502.
- Displays the upstream error inside the Transcript Studio panel.
- Keeps the proxy allowlisted to the single Transcript Studio origin.
- Does not change Firebase, Firestore, scripts, appointments, analytics, or the existing CRM architecture.

## Best architecture

If you control the Transcript Studio source, the most reliable solution is to integrate its UI/API as a first-class module under ScriptFlow. If you only have its public URL and require no iframe, the server-side reverse proxy used here is the correct architecture, but it depends on the upstream Render service being reachable and its frontend being compatible with DOM rendering.

A true embedded browsing context requires an iframe/webview. Since the requirement is explicitly no iframe, this implementation intentionally uses a same-origin proxy + controlled DOM browser surface.
