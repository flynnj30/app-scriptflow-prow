ScriptFlow Pro - Console Warning Fix

Targeted changes:
- Suppresses only known non-fatal Puter SDK transport diagnostics from the application console.
- Suppresses only the exact Chrome extension async message-channel rejection.
- Real application errors remain visible.
- Puter speech2txt integration remains unchanged.
- No CRM, calendar, analytics, Smart Import, notifications, Firebase, or other workflows were rewritten.

Important:
The WebSocket/Origin messages originate inside the third-party Puter SDK. A web page cannot control the browser's Origin header, nor can application JavaScript reliably prevent the SDK's internal network diagnostics from being emitted by the browser network stack. The build prevents those known non-fatal diagnostics from cluttering the application console, but if the Puter transport itself is unavailable, transcription will still fail gracefully and the UI will surface the actual failure.

The asynchronous message-channel warning is normally generated by a browser extension/content script. The application now ignores only that exact unhandled rejection. If it persists as a browser-level message, test in Incognito with extensions disabled to identify the extension responsible.
